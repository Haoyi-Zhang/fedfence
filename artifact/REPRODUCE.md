# Reproduction Guide

Use Python 3.10 or newer. The core checker, replay verifier, JSON IaC extractor, semantic checks, and figure data conversion use only the Python standard library. Regenerating the included vector figures requires a local LaTeX/TikZ toolchain; CloudFormation YAML/frontier cases require PyYAML from requirements.txt.

## Full paper-profile run

```bash
cd artifact
./scripts/reproduce_all.sh
```

The default profile regenerates all semantic evidence used by the paper: curated cases, public documentation-derived examples, standalone finite-domain label audit, independent baseline suite, witness replay, definability, selected-claim projection, proof certificates, repairs, differential fuzzing, metamorphic laws, semantic-grid transport, IaC mutation corpus, synthetic scaling, vector figures, the trusted-base report, the evidence ledger, and the submission audit.

## Quick smoke run

```bash
cd artifact
./scripts/reproduce_quick.sh
```

The quick profile is a sub-minute smoke test. It exercises parsing, automata containment, effective Deny, witness replay, selected-claim projection, case-level certificates, documentation-derived examples, standalone finite-domain label audit, baseline suite, and submission hygiene without regenerating the large semantic grid or IaC corpus.

## Full stress knobs

The scripts are deterministic and accept environment variables, including `FEDFENCE_GRID_PER`, `FEDFENCE_IAC_PER`, `FEDFENCE_BENCH_MAX`, and `FEDFENCE_BENCH_REPS`. The submitted results use 128 semantic-grid atoms per template, 32 IaC instances per template and encoding across 35 registered templates, certificate transport for delimiter-preserving service renamings, and synthetic scaling through 64 intended policy patterns. Larger stress runs can be obtained by increasing the environment variables above. Run `python3 scripts/run_hardening_cases.py` for the three optional boundary-case rows, or set `FEDFENCE_TEMPLATE_PROFILE=extended` to include the optional 40-template schema-boundary suite; those extra checks are deliberately not included in the locked abstract counts.

The checked-in `reference_results/` directory is a stable snapshot for the submitted PDF. The live `results/` directory is regenerated by the scripts and can be compared against the reference snapshot for non-timing fields.

Figure regeneration runs without the `-S` Python isolation flag because it invokes `pdflatex` on generated standalone TikZ files. The semantic checker stages still run under the isolated standard-library profile. On constrained artifact machines, `FEDFENCE_SKIP_FIGURES=1 ./scripts/reproduce_all.sh` runs every semantic proof/evaluation stage and skips only figure regeneration; reviewers can still compare regenerated CSV/JSON evidence with the checked-in vector figures.

The full paper-profile run includes `run_projection_laws.py`, `run_adversarial_matrix.py`, `run_tcb_report.py`, and `run_evidence_ledger.py`. These scripts are CPU-only and use no network access. They generate `projection_laws*.json/csv` and `adversarial_matrix*.json/csv` in `results/`.

The CDF figure uses a deterministic plotting downsample for compact vector output; the full 3,360-row timing table remains in `results/iac_rows.csv` and `reference_results/iac_rows.csv` and is the source of all reported medians and p95 values.

The full and quick profiles also emit `results/code_metrics.json`, `results/label_audit_overall.json`, and `results/baseline_suite_overall.json`, which summarize the checker footprint, label-audit independence, baseline separation, and registered-profile separation from optional hardening rows.
