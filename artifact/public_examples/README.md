# Public evidence examples

These examples are hand-normalized from public documentation, public issue discussions, public gists, and public troubleshooting posts.  They are not a prevalence study and are not claimed to be a representative sample.  Their purpose is narrower: to show that the semantic classes used by the calculus correspond to patterns that appear outside the generator.

Account identifiers are replaced with zeros, owner and repository names are normalized where needed, and each example supplies an explicit intent and governance premise.  The source URL is retained in each JSON file so artifact evaluators can inspect the provenance of the pattern without relying on hidden data.

The suite covers repository suffix wildcards, organization and multi-repository wildcards, exact branch subjects, exact environment subjects with and without repository-scoped governance, custom audience restrictions, condition-key namespace mistakes, substring-principal rejection, and Deny-based attempts to recover from a broad Allow.
