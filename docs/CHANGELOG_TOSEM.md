# In-place TOSEM revision

The comparison baseline is the user's `FedFence_FSE_Submission_Package(1).zip`. The original regular-language analysis files in `artifact/fedfence/` remain the inherited core. The original `fse_workflow` namespace is retained.

## Semantic and implementation changes

1. **Shared decision rule.** The strict gate and public study now use the existing shared invalid-first decision resolver. Invalid required identities, inconsistent premises and unsupported evidence cannot be hidden by an apparent overgrant or positive loss.
2. **Strict fragment boundary.** Mixed exact provider ARNs are refused rather than merged under the subject/audience projection. Analysis budgets must be finite, positive, numeric and non-Boolean. StringLike uses only `*` and `?`; brackets are literals. Positive token coordinates must be nonempty strings, and issuer mintability and intent membership are checked before reporting loss.
3. **Finite explicit-issuer adapter.** Finite models retain whole identity tuples, materialize one-shot iterables once, reject coordinate coercion, preserve invalid findings and compare the complete replayed decision rather than a status label alone. Its explicit finite scope remains visible.
4. **Complete review receipts.** The new `receipt.py` attaches to the existing gate. It binds the packet and its two-sided semantic result, checks the envelope digest, reruns current code using caller-time freshness, and compares the complete semantic view, including dependency implementation digest and positive obligations. A receipt is not authenticated and is not a cache. CLI reads a packet once for both review and receipt construction.
5. **Corrected public study.** The existing correction records are actually applied: sports-store roles are distinct, and microticket's empty/default and observed-binding branches are separate. Repair checks now compare semantic membership instead of accidentally comparing unlike Python containers.
6. **Reproduction repair.** The Makefile, final compatibility wrappers and TOSEM driver use `../paper/`, not historical paper paths. The second revision used nine local evidence steps produce the current authoritative results. Generated numbers are tied to JSON outputs.
7. **Honest trust boundary.** Source authenticity, reviewer identity verification, workflow reachability, runtime verification and deployment authorization are not asserted. The review record binds supplied approval metadata and content, not a cryptographic identity.

## Validation added or rerun

The initial unchanged baseline ran 94 tests. Eighteen regression methods in the first TOSEM revision raised the suite to 112. The second revision adds 34 boundary methods, for 146 executed tests with no failures/errors/skips. The original 3,945 core self-checks are rerun. New finite two-sided, strict differential, relational, dependency-transform and isolated seeded-fault checks are included. Each seeded fault has a passing unmodified control before a single benign local semantic change is tested; no real target is involved.

Public patch hashes, source-assertion strings, source-excerpt hashes and maintenance record hashes are checked only against the supplied snapshots. No remote source provenance is inferred from them. No full-source extractor, external product, repository workflow or real cloud account was executed.

## Paper changes

The original conference text is replaced by a complete journal manuscript, not by renamed conference metadata alone. It develops the state/observation model, two-sided obligations, realizability and relational proofs, strict fragment, freshness and dependency semantics, replay distinctions, implementation boundary, multi-layer evaluation, corrected cases, related work and validity analysis. At the second-revision checkpoint the paper had 62 used references, nine editable vector figures and twelve tables. That checkpoint had 39 total review-format pages, without manually inflated fonts, spacing or margins.

The original manuscript and superseded audit notes remain clearly marked under `tosem/history/` as provenance. A source-level inventory and unified diff against the uploaded original are supplied as `SOURCE_CHANGE_INVENTORY.json` and `implementation_changes.patch`; generated outputs and historical copies are excluded from the implementation patch.

## Second revision from the prior TOSEM delivery

The positive checker now uses an exact bounded prefix matcher rather than regular-expression backtracking. It aligns empty-string alternatives and typed issuer/audience refinements with the preserved core. Explicit invalid clock values do not select wall-clock time, source references must be strings, optional policy IDs must be strings, and policy version omission is rejected. Huge timeout integers and excessively nested malformed values return insufficient evidence rather than escaping as uncaught exceptions. A shared monotonic budget includes positive checks, including an empty positive set.

New executable checks cover 242,580 matcher pairs, 2,304 issuer memberships, 192 equality-bounded wildcard packets, and 54 local timing runs. The paper adds exactness/composition/freshness arguments and two vector figures. The build audits plot values, all bibliography ledger keys, unique labels, actual template identity and PDF hash. Assertions must be enabled during reproduction.

The current official template source identities were verified and an opt-in installer supplied. Download failure remains explicitly recorded; a v2.20 or TAPS validation is not fabricated.
