# S&P reviews to final FSE revision map

The source is the uploaded IEEE S&P 2027 review email containing reviews
#1711A-D. The table distinguishes work completed in this package from research
claims that still require external evidence.

| Review point | Final revision | Evidence path | Residual boundary |
|---|---|---|---|
| A: admitted states are a subset of saturation, not the whole saturation | Replaced the ambiguous statement with an admitted-state definition and universally safe observations | `docs/SEMANTICS_REVISION.md`, `fse_workflow/semantics.py`, finite audit | No proof that a supplied issuer state model is complete for live GitHub |
| A: all states versus issuer-mintable states | Restricts the state domain before projection; includes a regression with an unmintable intended state and a mintable unintended collision | `tests/test_semantics.py`, `fse/results/finite_semantics_audit.json` | Provider conformance remains external evidence |
| A: inclusion-minimal versus minimum-cardinality claim bases | API and tests return both concepts and preserve the empty basis for constant predicates | observation-basis implementation and tests | Not integrated as an automatic production subject-template synthesizer |
| A: missing important states | Missing/partial model coverage cannot produce a positive completeness claim; omission-sensitive tests return a bounded result only | strict packet/profile checks and semantics tests | Requires a maintained provider model and conformance process |
| A: claim refinement versus governance repair | Claim refinement splits observation classes; governance removes states only through a named external premise | manuscript Sections 3-4; `docs/SEMANTICS_REVISION.md` | Governance export authenticity/completeness is not proved |
| A: policy/governance changes after proof | Certificates bind digests and freshness of policy, issuer, workflow, governance, contract, and implementation; any dependency change forces review | packet schema, `fse_workflow/gate.py`, receipts | Hashes are not signatures or reviewer authentication |
| A: derivation and proof-to-code boundary | Keeps bounded audits and replay separate from theorem claims and states the shared TCB explicitly | manuscript Sections 4-6; 65,536-model audit; 3,945 predecessor self-checks | No Coq/Lean/Dafny refinement proof |
| A: 37-case selection and shared-component risk | Replays all 37 predecessor cases and inventories their backend/profile classes; adds a dispatch regression that prevents selected-claim Deny from reaching the two-claim backend | `legacy_case_replay.json`, `legacy_fragment_inventory.json`, `legacy_boundary_probe.json` | Curated cases remain non-representative |
| B: who writes intent and how it stays fresh | Adds a literal release contract with separate declared reviewer/reference/digest and dependency-bound snapshots | `fse_workflow/contract.py`, schema, examples | The package does not authenticate people or prove business intent correctness |

| D: practical application and effort | Provides a one-step PR integration path, strict output contract, eight executable walkthroughs, and local latency accounting | action/schema/examples/results | No participant study, authoring-time measurement, or production deployment |
| B/C/D: availability regressions | Adds finite required-token obligations so a safe-but-unusable edit can fail separately from overgrant | `fse_workflow/conformance.py`, availability walkthrough, compatibility case | Required examples are not a complete lower-bound availability language |

The final manuscript and artifact answer the configuration-review question that
can be supported locally. They deliberately withhold prevalence, field-accuracy,
product-superiority, owner-confirmation, and measured-usability claims.
